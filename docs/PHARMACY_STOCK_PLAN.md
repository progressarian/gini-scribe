# Pharmacy Stock Upload — Plan

A new **Pharmacy Admin** role uploads the DARPAN "Item Wise Stock Report" (.xlsx) whenever
they like. Each upload replaces the pharmacy's stock picture, and every screen that already
reads stock (dispense card, consultant Rx, Finalize, alternatives) starts showing real
quantities instead of "Stock —".

## 1. What already exists

| Piece                                                                                                                         | Where                                                                         | State                                                                                       |
| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `pharmacy_inventory` table (`medicine_name` UNIQUE, `stock_qty`, `reorder_level`, `price_per_unit`, `alternatives`, `source`) | `migrations/2026-09-02_consultant_prescription.sql`                           | Created **empty on purpose** — absence = "unknown", never "in stock"                        |
| Stock chips + out-of-stock alternatives on the dispense card                                                                  | `services/giniflow/medicineCard.js`, `pharmacyStation.js`, `DispenseCard.jsx` | Join `UPPER(i.medicine_name) = UPPER(COALESCE(m.pharmacy_match, m.name))`                   |
| Stock on the consultant's Rx draft + medicine search + alternatives                                                           | `services/giniflow/prescription.js`                                           | Same join on `rx_items.pharmacy_match`                                                      |
| Out-of-stock warning at Finalize                                                                                              | `services/giniflow/finalize.js`                                               | Same join                                                                                   |
| xlsx parsing (exceljs), raw-body upload, preview → commit                                                                     | `routes/billingImport.js`, `services/billing/importParse.js`                  | Pattern reused, not the code (billing's sheets/columns are specific)                        |
| `src/medicine_db.json` (990 brands)                                                                                           | voice → Rx matching (`src/medmatch.js`)                                       | Built from the same DARPAN list: `raw` = DARPAN item name, `brand` = name written on the Rx |

So **nothing that reads stock needs to change**. The work is: a role, an upload, a name-link
table, and a writer that rebuilds `pharmacy_inventory` from the latest upload.

## 2. The source file (DARPAN "Item Wise Stock Report")

- Rows 1–3: title, `GENERATED BY: <user> [dd/mm/yyyy hh:mm:ss AM]`, `STORE NAME: …`
- Row 5: header — `Item name, Total Stock, Company Name, Generic Name, Item Category,
Item Sub Category, Item Type, Schedule Drug, Location, P.RateTot, LP.RateTot, S.RateTot,
PTR wise Diff, LP wise Diff`
- Item rows, then a blank row and a `TOTAL` row (ignored).
- Only items **with stock** are listed (no zero rows) → an item missing from a new upload is
  **out of stock** (decision §9.1).
- `*RateTot` are totals for the whole quantity; per-unit = total ÷ qty.
- Known data problems surfaced as **warnings** (not blocking): purchase rate ≈ 0 (9 items in
  the 05/10/2026 file), blank category/company/generic, duplicate item names.

Parser finds the header row by name (not by fixed row number), so a column move or an extra
title line does not break it. Missing required columns (`Item name`, `Total Stock`) → reject.

## 3. Role and permissions (`shared/permissions.js`)

- New role `pharmacy_admin` = everything `pharmacy` has **plus**:
  - `PHARMACY_STOCK_VIEW` — the stock list page
  - `PHARMACY_STOCK_UPLOAD` — upload/commit sheets, link names, see purchase rates & margins
- `pharmacy` gets `PHARMACY_STOCK_VIEW` only (qty + sale price; purchase/landing rates and
  margins are stripped **server-side**, not just hidden).
- `admin` already holds every capability.
- Login page role group "Pharmacy Admin"; user creation accepts the new role through the
  existing `normalizeRole` path (unknown roles still fail closed to guest).

## 4. Data model (migration `2026-11-09_pharmacy_stock.sql`)

```
pharmacy_stock_uploads          one row per uploaded file
  id, file_name, store_name, report_generated_at, uploaded_by, uploaded_at,
  status ('preview' | 'committed' | 'discarded'), committed_at, committed_by,
  item_count, total_units, purchase_total, landing_total, sale_total,
  missing_count (items that will drop to 0), warnings JSONB

pharmacy_stock_upload_lines     the file, row by row (audit + diff)
  upload_id, row_no, item_name, item_key (normalised), qty, company, generic,
  category, item_type, purchase_total, landing_total, sale_total, warnings TEXT[]

pharmacy_stock_items            current state per DARPAN item (one row per item_key)
  item_key UNIQUE, item_name, qty, company, generic, category, item_type,
  purchase_total, landing_total, sale_total, unit_sale_price,
  in_latest BOOLEAN, last_upload_id, updated_at

pharmacy_stock_links            DARPAN item  →  name(s) prescriptions use
  item_key, medicine_key (UPPER canonical Rx name),
  status ('identity' = the DARPAN name itself | 'auto' = medicine_db match | 'confirmed' = admin),
  created_by, created_at       PK (item_key, medicine_key)
```

`pharmacy_inventory` stays the **read model** every station already queries; it is rebuilt
from `pharmacy_stock_items` + `pharmacy_stock_links` on each commit (§6). Rows it owns carry
`source = 'darpan'`; manual/demo rows (`source <> 'darpan'`) are never touched.

## 5. Name linking (DARPAN name → prescription name)

Prescriptions store `pharmacy_match` (= `canonicalMedKey(name)`), and for voice/Scribe Rx
the name is the `brand` from `medicine_db.json`. Linking, in order:

1. **Auto, exact** — `medicine_db.json` entry whose `raw` equals the DARPAN name → link to its
   `brand` (681 / 1,040 items in the current file).
2. **Auto, identity** — the DARPAN name itself (canonicalised) is always a key too, so a
   prescription typed exactly as DARPAN spells it matches.
3. **Suggested** — for the rest, top candidates by token overlap against `medicine_db` brands
   and the most-used prescription names (`medications.pharmacy_match`); strength numbers
   (`10`, `500MG`, `15MG`) must agree, pack tokens (`TAB`, `1*10`, `10S`, `KIT`…) ignored.
   Shown to the admin, **not** applied until confirmed.
4. **Manual** — admin searches and adds any prescription name; can add several (e.g. HealthRay
   spells it differently from Scribe) or remove a wrong one.

Links are keyed by `item_key`, so they survive every future upload — the admin confirms once.
"Not linked" (filter + summary) means the item has no `auto` or `confirmed` link; an `identity`
link alone does not count. On the 05/10/2026 file: 680 items link automatically, 359 need the admin.

## 6. Upload flow

```
Pharmacy Admin → Pharmacy Stock page → choose .xlsx
   POST /api/pharmacy/stock/uploads           (raw body, ?fileName=)   → status 'preview'
        parse → lines → diff vs current items
   ← preview: totals, new items, qty changed, unchanged, going out of stock, warnings,
              items with no prescription link
   [Discard]  POST /api/pharmacy/stock/uploads/:id/discard
   [Apply stock update]  POST /api/pharmacy/stock/uploads/:id/commit
        one transaction:
          - upsert pharmacy_stock_items from lines (in_latest = true)
          - items not in this upload: qty = 0, in_latest = false
          - auto links (§5.1–5.2) for new items
          - rebuild pharmacy_inventory rows with source='darpan':
              one row per medicine_key, stock_qty = SUM(qty of linked items),
              price_per_unit = unit sale price, generic_name, drug_class = category
            rows whose key is no longer linked → deleted (back to "unknown")
          - upload.status = 'committed'
   ← summary; stock screens refresh
```

- Commit refuses a preview that is not the newest one, or one older than the last committed
  report (`report_generated_at`) — an old file can't overwrite newer stock by accident.
- Starting a new preview discards older un-committed previews.
- Limits: 5 MB, 5,000 rows; `.xlsx` only.

## 7. Screens

**`/pharmacy/stock`** (nav "💊 Stock", cap `PHARMACY_STOCK_VIEW`)

- Header: "Pharmacy stock" · last updated `<time>` from `<file>` by `<user>` · primary action
  **Upload stock sheet** (upload cap only).
- Summary tiles: items in stock, total units, sale value (purchase value + margin for admin).
- Filter row: search (item, company, generic), [All | In stock | Out of stock | Not linked].
- Table (compact): Item · Qty · Sale price/unit · Linked Rx names (chips) · Category ·
  (admin) Purchase total · Margin. Long names wrap; row opens a link editor (admin).
- Empty: "No stock uploaded yet — upload the DARPAN Item Wise Stock Report to start."

**Upload preview** (same page, replaces the table until applied/discarded)

- File, store, "generated by … at …", row count.
- Counts with expandable lists: New · Qty changed (old → new) · Going out of stock · Unchanged ·
  Warnings (e.g. purchase rate ≈ 0).
- Confirmation text states the consequence: "N items will be updated, M will be marked out
  of stock." Buttons: **Discard** / **Apply stock update**.

**Upload history** — file, by, when, items, units, status.

**Link editor** (dialog) — DARPAN item, current links, suggestions with Confirm, search box to
add a prescription name, remove link.

## 9. Decisions (confirmed 2026-10-05)

1. Item missing from a new upload → **out of stock (0)**.
2. Pharmacy Admin + Admin upload and see purchase rates/margins; Pharmacy sees a **read-only**
   list (qty + sale price).
3. Names: **auto-match + admin confirms**, remembered across uploads.

## 10. Phases

1. Role + capabilities + migration.
2. Parser + preview + commit + inventory rebuild (server) with e2e tests on the test DB.
3. Stock page, upload preview, history (client).
4. Link editor + suggestions.
5. Later (not in this change): regenerate `medicine_db.json` from linked stock so newly stocked
   brands are matchable by voice; low-stock `reorder_level` per item; scheduled DARPAN pull if
   DARPAN ever exposes an export API.

## 11. Risks

- **Wrong link = wrong stock shown on a patient's card.** Only exact matches auto-link;
  everything else waits for a human. Each link records who confirmed it.
- **Stale sheet.** Page always shows "updated <time> ago"; older report than the current one is
  refused at commit.
- **Purchase rates are commercially sensitive.** Stripped in the API for non-upload roles.
- Applying the migration on production is a manual step (`node migrations/_runOne.mjs …`).
